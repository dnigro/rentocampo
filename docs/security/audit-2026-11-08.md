## Limitations / operator actions

1. End-to-end two-account tests could not run: UAT project is marked ACTIVE_HEALTHY yet read-only database connection fails with password authentication error. The preview branch now has an isolated UAT publishable key, not a service-role key. Do not introduce a production secret into the preview. Fix UAT database access and provision a branch-scoped UAT server secret only if needed.
2. Supabase Security Advisor: one WARN for leaked password protection. Supabase organization is currently Free; this feature requires Pro or above and a billing decision.
3. Domain DNS is delegated to GoDaddy nameservers (`ns69.domaincontrol.com` and `ns70.domaincontrol.com`). DMARC must be checked and managed at the authoritative provider. Do not create inactive DNS records at Vercel. A safe initial policy to evaluate is `v=DMARC1; p=none; adkim=r; aspf=r`, then move toward quarantine/reject once alignment is verified.
4. Four Resend API keys exist, but individual live usages cannot be proven from currently available logs; rotate/revoke only with controlled replacement to avoid email downtime.
5. Publishing still uses free-growth mode. Trusted-user auto-approval and anti-spam limits need a separate explicit product moderation policy before new restrictions are enabled.
6. GitHub CI tests exercise validation and authorization logic; they are not a substitute for full authenticated browser acceptance tests or a penetration test.

## Rollback for permission phase only

If server writes unexpectedly fail, prefer reverting the application to a known working release first. For a temporary emergency DB rollback:
```sql
GRANT INSERT, UPDATE ON TABLE public.campos, public.servicios_publicaciones TO authenticated;
```
This reopens the bypass and should be time-limited; do not use unless necessary. Once the application is healthy, reapply the revocations.
